# 技能2 · 抓矿泉水瓶（Bottle Grasp）· 看见桌上的瓶子 → 伸手 → 包裹式抓握 → 搬运放下

[English](skill02_bottle_grasp_guide.md) | **简体中文**

**一句话**：Orin 上的相机用 YOLO 分割出桌上/箱子上的矿泉水瓶，借瓶子接触的支撑面深度反推出瓶子中轴线位置（瓶身透明测不到深度，绕过它），再顺手测出承载箱子的水平轮廓；x86 上的手臂用 MoveIt+QP 混合策略绕开箱子接近瓶子，五指包裹式抓握（不是像技能1那样单指点按），提起后由人交互式微调水平位置，下降放下、松手、收臂归位。

| 配套 | 路径 |
|---|---|
| 感知·瓶子（Orin 跑） | `skill/skill02_bottle_grasp/bottle_locator.py` |
| 感知·箱子（Orin 跑） | `skill/skill02_bottle_grasp/box_locator.py` |
| 运控（x86 跑，主文件） | `skill/skill02_bottle_grasp/grasp_bottle.py` |
| 配置常量（调参只改这里） | `skill/skill02_bottle_grasp/config.py` |
| 诊断工具（箱子检测可视化） | `skill/skill02_bottle_grasp/debug_box_overlay.py` |

> 本技能承接技能1的协调模式（感知+手臂+灵巧手拧成一个动作），但感知和抓握几何完全不同：技能1的目标是固定 AprilTag，本技能的目标是无标记的真实物体（矿泉水瓶），且瓶子旋转对称、姿态不需要跟随目标计算。手臂控制器仍是原子层 atom05~08 讲过的 MoveIt/QP，本文同样只讲怎么把它们协调起来，不重复展开单个控制器。

## 1. 速览（点进来先看这块）

### 1.1 跑起来

跨两块板子（天轶2.0 双板：Orin 感知 / x86 运控），两板须在同一个 `ROS_DOMAIN_ID` 下才能互通话题。

**① Orin（`nvidia` 用户）——起相机 + 两个感知节点：**

```bash
bash scripts/start_camera.sh                                    # 起 Orbbec 相机驱动
python3 skill/skill02_bottle_grasp/bottle_locator.py             # 终端A：检测瓶子，发瓶子位置
python3 skill/skill02_bottle_grasp/box_locator.py                # 终端B：借瓶子种子高度测箱子
```

两个节点都只做「看」，不动机器人，零风险，可以先单独跑、拿 `ros2 topic echo` 核对数值是否合理。`box_locator.py` 依赖 `bottle_locator.py` 已经在发布箱顶高度这个种子值，必须先起 `bottle_locator.py`。

**② x86（`ubuntu` 用户）——起本体控制 + 跑主程序：**

```bash
sudo systemctl stop teleop_robot            # 遥控服务占 /arm/cmd_pos，不停则使能失败
bash scripts/start_body_control.sh          # 另开终端，等 "All devices ready."
bash scripts/start_xarm.sh real             # XARM 本体
source /home/ubuntu/XARM/install/setup.bash # 跑 demo 的终端 source 一次 XARM
python3 skill/skill02_bottle_grasp/grasp_bottle.py
```

**预期现象**（每个 `input()` 停下等你回车，看清坐标/画面再放行）：打印瓶子位置和算出的停驻点/闭合点坐标 → 回车 → 使能、开手、关节空间回预备姿态 → 三段式接近安全中间点/停驻点/抓握位（各停一次回车核对）→ 五指包裹闭合 → 竖直提起、回车确认抓稳 → wsad+回车 交互式微调水平位置、q 结束 → 下降放下 → 松手 → 先到安全中间点、再关节空间归位。

> ⚠ **执行前逐条确认（安全）**：
> 1. 箱子/瓶子摆好、**人退出手臂可达范围**。
> 2. 每一步 `input()` 回车前务必核对打印坐标/画面是否合理——这是感知或标定算错时**唯一**的人工拦截点，本技能没有软件层面的安全区校验。
> 3. QP 慢速 `VEL_LIMITS` + MoveIt `VEL_SCALE=0.1`，急停在手。
> 4. 出意外臂停半空：`python3 .../grasp_bottle.py --recover` 收臂（见第 6 节）。

> ⚠ **真机标定常量**：`READY_JOINTS`、`GRASP_ORIENT`、`GRASP_DIR`、`TCP_OFFSET`、`STANDOFF_MARGIN` 是针对当前这一套瓶子+手指装配标定的固定值。硬件、瓶子或工作位变化后，须由合格人员重新标定并验证。

### 1.3 心智模型：三段式接近 + 安全中间点

跟技能1不同，本技能的接近不是「一步到位+闭环补刀」，而是**三段接力**，专门为了绕开箱子：

```
①a MoveIt(末端,容差松) ──▶ 安全中间点（箱子y方向最远处+余量，不做竖直抬高）
                              │(回车确认没蹭到箱子)
①b QP(末端,精确) ────────▶ 预抓停驻点（顺带把姿态收到 GRASP_ORIENT）
                              │(回车确认)
③  QP(末端,精确) ────────▶ 最终抓握位置（沿 GRASP_DIR 精修平移）
```

| 阶段 | 控制器 | 为什么 |
|---|---|---|
| ①a 到安全中间点 | MoveIt，姿态容差故意放松 | 大范围移动会自动规划，但落地姿态不精确；中间点选在箱子外侧明显甩开箱子的地方，把"不确定会不会贴着箱子扫过"的风险限制在这一步 |
| ①b 中间点→停驻点 | QP，精确执行 | 只调 y/z，姿态顺带收到精确值，不需要再单独摆正姿态 |
| ③ 停驻点→抓握位 | QP，沿固定方向平移 | 姿态已锁死，最后一段行进方向才可信 |

MoveIt 独自做不到「姿态精确复现」，QP 独自做不到「大范围绕障」，两者分工缺一不可。**安全中间点是自己算出来的路径点，不依赖 MoveIt 的碰撞检测**——见 2.4。撤回阶段走一样的三段逻辑（反向）。

## 2. 四个核心概念

### 2.1 无标记感知：借支撑面深度，不测瓶身本体

透明塑料瓶身让结构光/双目深度算法大概率测不到有效值，这是本技能相比技能1（用醒目的 AprilTag 卡片）最大的不同——目标物体本身在深度图里几乎是"隐形"的。

解法：只借瓶子接触的**支撑面**（桌子/箱子，这类表面深度一直很干净）反推。YOLO-seg 分割出瓶子的像素 mask → 提取 mask 底部边界曲线（瓶底可见弧）→ 每个边界点借支撑面深度反投影成 3D 点 → 半径单独从 mask 中段宽度测（不受近侧弧病态问题影响）→ 固定半径最小二乘拟合出圆心。圆心就是瓶子中轴线在支撑面上的位置——这是"瓶子在哪"的答案，不是"该往哪伸手抓"的答案，后者由 `TCP_OFFSET` 承担。

箱子的检测则相反：箱子是不透明哑光大平面，深度相机的最佳案例。借瓶子已测出的支撑面高度当种子，直接对深度点云做"筛高度+求轮廓"就够了。

### 2.2 一次快照语义：两处都用，缺一不可

跟技能1一样，瓶子位置在 `wait_target()` 里凑够 `N_SAMPLES` 帧取中位数后就冻结，不再追踪移动目标。

**本技能额外多了一层**：箱子数据也是一次快照（`wait_box()`，`_box_snapshot_locked` 锁定），原因是 `box_locator.py` 全程持续运行、对"画面里出现的到底是箱子还是机器人自己的手/臂"没有分辨能力——如果不锁定，撤回阶段手臂经过箱子上方时可能被误判进箱子点云，导致安全中间点的计算基准突然失真（真机验证时出现过箱子边界值异常暴涨的情况）。两处快照都是同一套设计哲学：**宁可用一份略旧但可信的数据，也不要一份实时但可能被自己污染的数据**。

### 2.3 抓握几何：姿态整体固定，只有位置随瓶子变

瓶子旋转对称，不需要像技能1那样按目标法线算接近姿态。四个常量全部靠拖动示教实测（不是算出来的）：

- `GRASP_ORIENT`：手部姿态，全程不变
- `TCP_OFFSET`：瓶子实测位置到 tcp 目标的完整 3D 偏移，包含抓握高度、前伸距离、任何侧向偏移
- `GRASP_DIR`：预抓停驻点到最终闭合点的方向，也是接近的行进方向
- `STANDOFF_MARGIN`：停驻点比闭合点多退多远

标定方法见 `config.py` 文件内注释。**这四个常量是本技能最大的局限来源，详见第 4 节**。

### 2.4 不依赖 MoveIt 的碰撞检测

箱子不会注册进 MoveIt 的碰撞体系统——MoveIt 自带的避障是否精确检测手部几何存疑，作为教程代码不希望引入这种不确定性。

安全性**完全来自我们自己选的路径点**（`build_intermediate_point`）：箱子数据只用来算这一个中间点，不会传给 MoveIt 做碰撞检测。理解这一点很重要——这不是真正意义上的实时避障，是"选对了端点"，如果箱子实际位置/形状跟感知结果有较大出入，这层保护会失效，这也是每一步都保留人工 `input()` 确认的原因。

## 4. 局限性与安全隐患（务必读完再上真机）

本技能是探索性质的教程代码，服务于"跑通一条完整链路"这个目标，**没有做到工业级抓取该有的鲁棒性**。以下局限如果不清楚，真机测试时可能导致手臂/手部与箱子或周边环境发生碰撞，严重时会让关节顶到限位、损坏硬件——代码里保留的每一处人工 `input()` 确认和安全余量，都是为了兜住这类风险，**不要因为"跑起来嫌麻烦"就删掉这些确认步骤**。

### 4.1 抓握手型、位置、方向全部硬编码

`config.py` 里的 `HAND_GRASP_POSE`（手指闭合量）、`TCP_OFFSET`、`GRASP_DIR`、`GRASP_ORIENT`、`STANDOFF_MARGIN` 都是**针对当前这一个瓶子 + 当前这一副手指装配**，通过拖动示教实测出来的固定值：

- 换一个直径/高度不同的瓶子，这些常量大概率不再适用，需要重新标定，代码不会自动适配瓶子尺寸（虽然 `bottle_locator.py` 会测出直径，但当前完全没用于控制，只做日志参考）。
- 手指装配、灵巧手硬件如有变化（比如维修后重新组装），抓紧手型的具体数值也需要重新试，代码没有任何自动检测装配变化的机制。
- 这些常量描述的是一条**直线路径**（停驻点→闭合点沿 `GRASP_DIR`），如果瓶子实际摆放的朝向/角度跟标定时不同，抓握效果没有保证——瓶子是旋转对称的，标定时没有考虑瓶子本身朝向这个自由度，但如果箱子/桌面倾斜、瓶子歪倒，这条假设会被打破。

### 4.2 灵巧手没有力反馈，抓稳与否全靠人工判断

手型闭合到 `HAND_GRASP_POSE` 这个固定值就停，不是靠力控收敛到"感觉抓稳了"为止。代码不知道、也测不出瓶子有没有被抓变形、抓滑、或者压根没抓到——全靠竖直提起后人工目视确认（`input()` 那一步）。如果瓶子材质/重量差异较大，同一个闭合量可能过紧（压瘪瓶身）或过松（提起时滑落）。

### 4.3 没有真正意义上的闭环修正，精度完全依赖开环

手指是固定关节，没有标定"缺口相对 tcp"的偏移帧，代码测不到"瓶子有没有真的对齐进缺口"这个反馈量。`check_position` 核对的只是"QP 有没有精确执行到下发的目标"，不是"抓没抓对"。也就是说：**如果感知有偏差（比如瓶子定位差了 2cm），运控会精确地把手送到一个错误的位置，不会自我修正**。精度完全压在感知准确度和几何常量标定准确度上。

### 4.4 搬运阶段纯开环，没有碰撞/支撑面检测

`interactive_jog_place` 让人用 wsad 键手动微调提起后的水平位置，但代码不会检查新位置下方是否真的有支撑面——如果人为操作失误把瓶子挪到箱子边缘外再下降，瓶子会直接悬空掉落。这一步的安全性完全依赖操作者的判断，不是软件保证的。

### 4.5 安全中间点不是真正的避障，只是一个估算出来的绕行点

见 2.4：箱子数据不参与 MoveIt 规划，`build_intermediate_point` 算出来的中间点是基于箱子检测结果的**一次性估算**，不是运动过程中的实时碰撞检测。这意味着：

- 如果箱子检测本身有误差（遮挡、光照、边缘漏点），中间点的安全性也会跟着打折扣。
- 中间点只在 y 方向绕开箱子，没有对箱子以外的其它障碍物（比如箱子旁边的其它物体）做任何处理。
- 一旦手臂离开中间点、进入 QP 精确接近段（①b/③），**这一段完全没有绕障逻辑**，只能靠标定值本身准确、以及箱子摆放位置跟标定时基本一致来保证安全。

### 4.6 箱子感知持续运行，存在被机器人自身遮挡/误判的风险

`box_locator.py` 全程持续检测，对"画面里出现的到底是箱子还是机器人自己的手/臂"没有分辨能力（2.2 提到的一次快照语义就是为了规避这个问题，把使用窗口限制在手臂还没进入相机视野之前）。如果需要在动臂过程中持续获取箱子最新状态（比如箱子会被人为挪动），当前设计不支持，需要额外加入手臂自遮挡过滤逻辑。

### 4.7 单瓶子假设，无遮挡/多目标处理

`bottle_locator.py` 检测到多个候选瓶子时只取置信度最高的一个，没有为多瓶子场景设计筛选逻辑；瓶子被遮挡超过一定比例（有效边界点不足 `MIN_BOUNDARY_POINTS`）会直接跳过该帧，不会给出退化的估计值。

### 4.8 依赖固定的相机外参标定

`EXTRINSICS_GROUP` 复用的是头部回零姿态下标定的外参组；如果实际运行时头部俯仰角跟标定时不同，会引入系统性偏差，代码不会自动检测或提示这种情况（只在文档/注释里提醒人工核对）。

| 改什么 | 会怎样 / 何时改 |
|---|---|
| `INTERMEDIATE_Y_MARGIN` | 安全中间点在箱子最大 y 边界基础上再留的余量，越大越保守，但太大可能导致中间点超出手臂舒适可达范围 |
| `BOX_XY_MARGIN` | 箱子长宽拟合结果本身再加的余量，兜的是深度点漏检导致的边缘低估 |
| `STANDOFF_MARGIN` | 停驻点沿 `GRASP_DIR` 退多远，只影响这一个距离，不影响其余几何常量；真机验证时留意这个距离手是否真的完全清空瓶子 |
| `HAND_GRASP_POSE` | 抓紧手型的闭合量；换瓶子或手指装配后须由合格人员重新标定并验证 |
| `PLACE_JOG_STEP` / `PLACE_JOG_MAX_TOTAL` | 搬运微调的单步幅度/累计上限，太大容易一按就冲过头 |
| `CONF_THRES` | YOLO 检测置信度门槛，光照差/瓶子被部分遮挡时可以适当调低，但要留意误检 |
| `BOX_HEIGHT_TOL` / `BOX_SEARCH_RADIUS` | 箱子检测的高度容差/水平搜索半径，箱顶候选点太少（`BOX_MIN_POINTS`）时适当放宽 |

## 6. 排错 / 进阶

| 现象 | 原因 / 处理 |
|---|---|
| 超时未收到瓶子目标 | Orin 上 `bottle_locator.py` 没跑 / 瓶子不在视野 / 两板 `ROS_DOMAIN_ID` 不一致 |
| 超时未收到箱子数据 | `box_locator.py` 没跑，或它还没收到 `bottle_locator.py` 的种子高度；此时安全中间点算不出来，接近/撤回会跳过这层保护直接走单段路线，务必留意日志警告 |
| `error_code=99999`（MoveIt 阶段秒失败） | 同技能1/atom05：多半是起点越界或过约束，参考 atom05 guide 排错表 |
| 中间点/停驻点确认时发现手臂离箱子很近 | 立刻 Ctrl-C，跑 `--recover` 收臂；检查 `INTERMEDIATE_Y_MARGIN`/`BOX_XY_MARGIN` 是否需要调大，或箱子检测本身是否准确（用 `debug_box_overlay.py` 核对） |
| 抓握后提起发现瓶子滑落/被压瘪 | 停止测试，由合格人员重新标定并验证 `HAND_GRASP_POSE` |
| 臂停在半空（段失败/Ctrl-C/崩溃） | `python3 skill/skill02_bottle_grasp/grasp_bottle.py --recover`，按落盘出发位 QP 慢速原路退回、再关节归位 |

- **`--recover` 收臂**：每次动臂前出发位姿已落盘 `_last_start_pose.json`，逻辑同技能1。
- **重新标定抓握几何**：须由合格人员记录预抓停驻位、最终闭合位和同期瓶子位置；计算关系见 `config.py` 注释。
- **看细节日志**：跑时加 `--ros-args --log-level debug`。
