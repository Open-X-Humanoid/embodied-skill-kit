# 运控8 · 手臂（Arm）· 力位混合模式（Force-Position Hybrid）

[English](motion08_arm_force_position_guide.md) | **简体中文**

**一句话**：向话题 `/arm/cmd_ctrl` 发一条 `CmdMotorCtrl`，在位置目标上叠加速度/力矩前馈，用 `kp`/`kd` 调节关节刚度；测试结束后用 `/arm/cmd_pos` 回起点。建议先看 motion03（位置模式）。

| `atom/motion/motion08_arm_force_position_ros2.py`（ROS2 原生版）、`atom/motion/motion08_arm_force_position_ros2_robust.py`（生产版） |

## 1. 速览（点进来先看这块）

### 1.1 跑起来

前提：已按《前置 · 环境配置》（`docs/environment_setup_zh-CN.md`）起好 body_control。

```bash
ssh ubuntu@<机器人IP>
source /home/ubuntu/ros2ws/install/setup.bash   # 每个新终端都要执行
python3 atom/motion/motion08_arm_force_position_ros2.py
```

预期现象：关节 12（左肩侧展）朝一个方向转动约 0.5rad（≈28.6°），保持 5 秒（此时可用手轻推关节感受柔顺性），随后自动用位置模式回到起始角度并退出。

⚠ **务必先读**：手臂力矩大、范围大；先确保臂周围无人无物，急停在手边。

⚠ **换右臂不要只改关节号**：左右臂 J2（肩侧展）关节角方向镜像——左 12 限位约 `-0.26~2.61`（外展为正），右 22 约 `-2.61~0.26`（外展为负）。demo 默认 `CTRL_DELTA=+0.5` 按左臂外展设计；若只把 `DEMO_JOINT_ID` 改成 `22` 而不把增量改为负值，会向体内收，有撞躯干风险。改测右臂应同时设 `CTRL_DELTA=-0.5`，并核对目标仍在该关节限位内。

### 1.2 接口


| 项     | 值                                                           |
| ----- | ----------------------------------------------------------- |
| 控制话题  | `/arm/cmd_ctrl` → `bodyctrl_msgs/CmdMotorCtrl`              |
| 回位话题  | `/arm/cmd_pos` → `bodyctrl_msgs/CmdSetMotorPosition`（仅用于收尾） |
| 状态话题  | `/arm/status` → `bodyctrl_msgs/MotorStatusMsg`              |
| 电机 ID | 左臂 11-17，右臂 21-27（1=肩 … 7=腕）；本 demo 默认 12（左肩侧展）             |


本简洁版**不做任何校验**（目标位置是否越界、`kp`/`kd` 是否在合法范围内、发布者是否就绪，全部裸发）；生产版 `motion08_arm_force_position_ros2_robust.py` 补齐了这些校验，见第 6 节。

## 2. 力位混合模式详解

**什么是力位混合**：在位置目标的基础上叠加速度前馈和力矩前馈，输出力矩 = `kp` × (目标位置 − 当前角度) + `kd` × (前馈速度 − 当前角速度) + 前馈力矩。

`kp`、`kd` 决定关节「刚度」：小值 → 柔顺（可被外力推开）；大值 → 刚硬（抵抗外力）。

**消息格式**：

```python
# bodyctrl_msgs/CmdMotorCtrl
std_msgs/Header header
MotorCtrl[] cmds

# bodyctrl_msgs/MotorCtrl
uint16  name   # 电机 ID
float32 kp     # 位置增益（范围 0~2000）
float32 kd     # 速度增益（范围 0~300）
float32 pos    # 目标位置 (rad)
float32 spd    # 前馈速度 (rad/s)，纯位置跟踪时填 0.0
float32 tor    # 前馈力矩 (Nm)，纯位置跟踪时填 0.0
```

**demo 参数**：`kp=15`、`kd=1.5`（柔顺）、`pos = start + 0.5 rad`，保持 5s 后回初始位（保持期内可用手轻推关节测试柔顺性）。

**适用场景**：阻抗控制、接触力调节、手臂被动跟随。

⚠ **"柔顺"是相对的，不是"没有阻力"**：手动推关节感受柔顺性时，若仍觉得偏"僵硬"，先分辨两种情况——

- **慢慢推**感觉硬：主要是 `kp` 在起作用（力矩与位置误差成正比），试着把 `CTRL_KP` 调到 10 甚至更小，对比手感变化。
- **快速推/松手回弹**感觉硬：主要是 `kd` 在起作用（力矩里的速度阻尼项，抵抗你推动的速度），试着把 `CTRL_KD` 调小（如 1-2）。
- 天轶手臂关节是大扭矩直驱/准直驱关节（肩部关节扭矩系数 2.4-3.4 Nm/A，额定扭矩 10-35Nm），并非小型舵机；同样的 `kp/kd` 数值，在这类关节上产生的绝对阻力矩会比想象中大。想获得更直观的"软"对比，可以换到扭矩系数和额定扭矩都更小的腕部关节（`DEMO_JOINT_ID = 16` 或 `17`）再试一次。

⚠ **"到位精度"和"柔顺性"是天然取舍**：`kp/kd` 越软，目标偏移量越大时越容易被重力/摩擦"吃掉"一部分位移——实际到达角度可能小于目标 `CTRL_DELTA`。日志会同时打出实际 Δ 与目标 Δ 便于对照；若要"又软又准"，通常需更完整的阻抗控制（如重力补偿前馈 `tor`），而不是单纯调 `kp/kd`。

## 3. 代码解读（核心）

`motion08_arm_force_position_ros2.py` 沿用 motion03 等原子的"简洁骨架"，只比最简版多了一个「保持期内持续 spin」的小助手。

### 3.1 模块地图


| #   | 模块       | 代码锚点                                                     | 职责                                     |
| --- | -------- | -------------------------------------------------------- | -------------------------------------- |
| 1   | 配置常量     | 话题名 / `CTRL_KP` / `CTRL_KD` / `CTRL_DELTA` / `CTRL_HOLD` | 调参改这里                                  |
| 2   | 建节点与收发   | `ArmForcePositionDemo.__init__`                          | 建 `pub_ctrl` + `pub_pos` + status 订阅   |
| 3   | 读状态回调    | `_on_status`                                             | status 帧 → `cur_pos`（当前角）              |
| 4   | 等当前角     | `wait_for_status`                                        | 与 motion03 相同，spin 到读到关节角                |
| 5   | 保持期 spin | `_spin_hold`                                             | 保持期内持续 `spin_once`，让 `_on_status` 保持更新 |
| 6   | 回位       | `_return_to`                                             | 用位置模式将关节送回初始角                          |
| 7   | 核心逻辑     | `move_ctrl`                                              | 发送力位混合指令 → 保持 → 打印实际位移 → 回位            |
| 8   | 主流程      | `main`                                                   | 读起点 → 执行 → 关停                          |




### 3.2 关键设计点

**为什么保持期用** `_spin_hold` **而不是** `time.sleep`**？**
`time.sleep` 会阻塞整个线程，`_on_status` 回调在此期间完全不会被触发，`cur_pos` 就是「保持期开始那一刻」的旧值——日志里打印的实际位移就会是错的。改用 `rclpy.spin_once` 轮询后，保持期内能持续收到 `/arm/status`，结束时读到的才是真实的最新角度。

## 4. 改一改，看变化


| 改什么                                        | 会怎样                                            |
| ------------------------------------------ | ---------------------------------------------- |
| `CTRL_KP = 30`                             | 更刚硬，关节抵抗外力推开                                   |
| `CTRL_KP = 10`、`CTRL_KD = 1`               | 更柔顺，更容易用手自由推动，但到位精度会更差                         |
| `CTRL_DELTA = 1.0`                         | 目标偏移量加倍，注意提前核对目标角度是否仍在该关节机械范围内                 |
| `DEMO_JOINT_ID = 22` 且 `CTRL_DELTA = -0.5` | 改测右臂 J2 外展；**必须**同时取反增量（左右 J2 方向镜像），只改 ID 会向内收 |


⚠ **合法范围 ≠ 一定安全**：`kp` 合法上限到 2000、`kd` 到 300，但即便落在范围内，取值偏大时关节会明显更"硬"、跟踪更猛，位移可能很快，仍有夹碰风险。改参请从小步开始（例如先把 `CTRL_KP` 从 15 调到 20~30 观察手感与到位速度），确认无异常再继续加大；调大 `CTRL_DELTA` 时同样先核对目标是否仍在限位内，并预留急停。

先预测结果再跑，看是否和预期一致。

## 5. 排错


| 现象                               | 原因 / 处理                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| 关节完全不动                           | body_control 未启动，或该话题没有订阅者：`ros2 topic list \| grep arm` 确认话题在，`ros2 topic info /arm/cmd_ctrl --verbose` 确认 Subscription count > 0 |
| 关节停在中途（没回初始位）                    | `_return_to` 使用位置模式，确认 body_control 接受 `/arm/cmd_pos`                                |
| 手感偏"僵硬"                          | 见 §2 末尾的柔顺性排查说明：区分 `kp`（慢推手感）和 `kd`（快推手感）分别调小，并注意大扭矩关节本身阻力矩绝对值就比小舵机大                 |
| 实际 Δ 明显小于目标 Δ                    | 这是柔顺性和到位精度的天然取舍（见 §2 末尾），不是 bug；想更精确到位可适度调大 `CTRL_KP`                                |
| `import bodyctrl_msgs` 报错        | 没 source：`source /home/ubuntu/ros2ws/install/setup.bash`（每个新终端都要）                    |
| **生产版** 打印「超出软限位」/「差值 > 上限」后拒绝运动 | 目标角度或改大的 `CTRL_DELTA` 超出了该关节的安全范围，属于设计内保护，调小 `CTRL_DELTA` 或核对 `DEMO_JOINT_ID` 对应的限位表 |
| **生产版** 打印「kp/kd 超出合法范围」后拒绝运动    | `CTRL_KP`/`CTRL_KD` 改得超出了 `0~2000`/`0~300` 合法范围，按范围内的值重新设置                           |
| **生产版** 保持期提前结束并打印 `error`       | 说明保持期内这个关节触发了故障码（过流/堵转等），已提前回位；参照 `MOTOR_ERROR_DESC` 定位具体原因                          |

## 6. 进阶

**生产级加固**（`motion08_arm_force_position_ros2_robust.py`）：相对简洁版，生产版新增了以下校验和保护，和 `motion03_arm_ros2_robust.py`/`motion01_head_ros2_robust.py` 是同一套路子，只是多了两条力位混合模式特有的：


| 加固点       | 简洁版行为                                      | 生产版行为                                                                               |
| --------- | ------------------------------------------ | ----------------------------------------------------------------------------------- |
| 发布者就绪     | 直接 `publish`，DDS 未匹配上时首包静默丢失               | `wait_publisher_ready` 等到至少一个订阅者才继续                                                 |
| 状态超时      | 读不到 `/arm/status` 就假设当前角度=0.0（有跳变风险）       | 超时返回 `None`，调用方直接拒绝运动                                                               |
| 目标位置      | 不校验，越界后果是撞机械限位或触发过流保护                      | 软限位（`JOINT_SOFT_LIMITS`）+ 单步幅度（`MAX_DELTA_RAD`）双重校验，超限直接拒绝                          |
| `kp`/`kd` | 不校验，改参数手滑填错直接发出去                           | 校验是否落在合法范围内（`kp:0~2000`、`kd:0~300`）                                                 |
| 保持期异常     | `_spin_hold` 只负责保持 `cur_pos` 更新，不管 `error` | `_spin_hold_watch` 实时监视 `error`，一旦非 0（过流/堵转…）立刻提前结束保持并回位，不再傻等到 `CTRL_HOLD` 满时长      |
| 中断兜底      | 无——半途 Ctrl-C/异常，关节会停留在"被力控但没人管"的状态         | `move_ctrl` 用 `try/finally` 包住保持逻辑，无论正常结束、提前因异常中止，还是被 Ctrl-C 打断，都会执行 `finally` 里的回位 |


⚠ 力位混合模式是「持续生效」的——指令一发出，关节就会一直被驱动向目标位置，直到收到新指令。这和位置模式的持续性质相同，但柔顺模式下更容易被人无意中推着继续动，所以生产版特别加了"无论如何都尝试回位"这条兜底；即便如此，**急停仍然应该在手边**，代码兜底不能替代物理急停。
